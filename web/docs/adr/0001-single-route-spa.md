# ADR-0001: Одностраничный SPA с внутренним переключением views

**Статус:** Принято

## Summary

Дашборд реализован как один Next.js-маршрут (`/`), который переключается
между шестью разделами (Overview, Playground, Metrics, Backends, Logs,
Architecture) через внутреннее состояние, вместо того чтобы создавать по
маршруту на каждый раздел.

## Контекст

В дашборде шесть top-level views без сколько-нибудь значимой URL-семантики —
это не ресурсы, а просто панели в консоли. Рассматривались два варианта:

1. **Мульти-маршрут** — `/overview`, `/playground`, `/metrics` и т.д., у
   каждого свой `page.tsx` и общий layout.
2. **Одностраничный SPA** — один `page.tsx`, поле `view` в Zustand-сторе и
   switch в shell-е.

Дашборд также запускается в изолированном preview-окружении, где наружу
торчит только dev-сервер. Deep-linking на конкретные разделы для портфолио
не требуется.

## Решение

Идём с одностраничным SPA. Состояние view живёт в Zustand-сторе; shell читает
`view` и рендерит соответствующий компонент. Горячие клавиши (`1`–`6`) и
командная палитра (`⌘K`) переключают разделы мгновенно, без сетевых
round-trip-ов.

## Последствия

**Положительные**

- Ноль бойлерплейта маршрутизации — никаких `loading.tsx`, `error.tsx` на
  каждый маршрут
- Мгновенное переключение разделов — без задержек на навигацию и без сдвига
  layout-а
- Zustand-стор становится единственным источником правды для всего, включая
  «где я сейчас»
- Работает в любом preview-окружении без настройки rewrite-ов

**Отрицательные**

- Нет deep-linking — нельзя добавить `/playground` в закладки
- Кнопка «назад» в браузере не переключает разделы (можно было бы починить
  через `history.pushState`, но для портфолио избыточно)
- Все разделы всегда в одном бандле — нет code-splitting-а по маршрутам

## Рассмотренные альтернативы

- **Next.js App Router с маршрутом на каждый раздел** — чище URL-семантика,
  встроенный code-splitting, но добавляет ~6 файлов бойлерплейта и заметную
  задержку навигации в нашем случае.
- **React Router внутри одного маршрута** — дал бы URL-ы без Next.js-роутинга,
  но лишняя зависимость, избыточная при таком количестве разделов.

Для production SRE-инструмента, который пользователи добавляют в закладки и
делятся ссылками, мульти-маршрут победил бы. Для портфолио-дашборда SPA —
правильный выбор.
